# C60 — Local structured diagnostics and report viewer

Added Logs in the actual app sidebar, using a uniquely labeled focus-contained dialog. It supports All/Error filters, Refresh, Copy report, native JSON export with cancellation/non-clobber behavior and Clear history. Reports include current product version/build identifier/platform; events retain their originating product version. Logs survive restart and are bounded to 500 events, 7 days and a 200 KiB file, stored in a private app-owned 0700 directory/0600 file. Corrupt logs are preserved until explicit clear; read/write/export paths reject symlinks or existing export files where applicable.

The schema accepts only enums for area/event/error code. No arbitrary message, request args, image data, filename, endpoint, password or exception stack crosses the log boundary. Unknown frontend codes become other; error.message is never recorded. Native FTP queue/start/completion/failure/recovery and frontend image/capture/preferences/clipboard failures are covered, including unhandled frontend errors. Logger failures do not interrupt image/upload operations. Curl exit categories follow the [official curl manual](https://curl.se/docs/manpage.html): connection/DNS, timeout, rejected login and certificate failure are static codes, not verbose server text. No automatic report upload/telemetry.

Validation: root Rust suite 37 passed, including schema secret rejection, persisted bounded rotation/expiry, corrupt-file preservation and non-clobber exports. Seven browser tests passed across Logs and FTP (two log cases, five FTP): copy/clear/export-cancel and raw password-like exception exclusion. Four existing native frontend boundary tests passed with diagnostics accounted for separately from capture dispatch. Production-entry typecheck passed. Actual one-time password migration is separate C59 work and its secret is absent from every report. Native OS Save dialog and real FTP diagnostics still require manual use.
