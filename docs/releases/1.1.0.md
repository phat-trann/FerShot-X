# FerShot X 1.1.0 candidate

Adds official Tauri 2 in-app updates: persisted daily checks, current/available versions, download progress and explicit download/install/restart. Settings and the cloud-sync tray item share one controller. Drafts flush before install/restart; active native image work and FTP transfer/deletion block installation. Startup uses monitor-cog with a trailing enabled tick.

Includes C95 capture presentation/hidden-canvas/wheel corrections and capture-specific scroll registration. Immediate upload is covered by injected success/failure recovery cases; real capture-to-FTP acceptance remains pending.

## C97 distribution policy

The user declines Developer ID/notarization and confirms the repository is public. The validated public key from the existing ~/.tauri/fershot-x.key.pub is embedded in base Tauri configuration. Only public material was read. Local bootstrap builds need no private key; GitHub release builds require the private updater key and its password if encrypted. Public-key overrides must match the pinned bootstrap key.

The macOS app is ad-hoc signed with signingIdentity "-". Updater archives retain required Tauri signatures. GitHub Actions builds universal Mac artifacts/latest.json, checks both architecture entries and cryptographic signatures, then publishes. It requires no Apple certificate/account secrets. See [setup and manual acceptance](UPDATES.md).

The configured bootstrap must be installed once in /Applications. It is not notarized: Gatekeeper, capture/Accessibility permissions and actual version-to-version replacement require manual acceptance. Phase-2 acceptance remains 85%. C98 user authorization permits committing/pushing this verification candidate at 85%; publication does not establish completed acceptance.

## C98 release trigger

Pushes to main publish a new stable version only when package.json increases relative to the push's previous commit. GitHub Actions creates the version tag and signed update assets automatically. Unchanged/decreased versions skip; published versions remain immutable. Manual dispatch can retry an unpublished version, while an existing draft tag must match its original source. The user will install and report remaining acceptance issues, then exercise Check for Updates with a later version.
